## Acceptance Criteria

### P0: Bus-Aware Data Types and Graph Construction
- [ ] CompilerPatch interface includes buses, publishers, listeners arrays
- [ ] GraphNode union type supports BlockOut and BusValue nodes
- [ ] GraphEdge union type supports Wire, Publisher, Listener connections
- [ ] buildDependencyGraph() creates complete graph with all node types
- [ ] Graph validation detects orphaned buses and invalid routing
- [ ] Bidirectional lookup maps enable efficient graph navigation
- [ ] Graph construction handles mixed wire/bus patches gracefully

### P0: SCC Detection and Feedback Loop Validation
- [ ] Tarjan's SCC algorithm implemented with O(V+E) complexity
- [ ] Memory block registry includes DelayLine, Integrate, SampleHold
- [ ] validateFeedbackLoops() allows only cycles crossing memory boundaries
- [ ] Error messages include cycle path and memory block requirements
- [ ] SCC detection handles disconnected components and nested cycles
- [ ] Cycle validation fails compilation with actionable errors
- [ ] Self-loops and multi-cycle patches handled correctly

### P0: Multi-Pass Compilation with Bus Artifacts
- [ ] topoSortBusAware() includes BusValue nodes in execution order
- [ ] compileBusValue() sorts publishers by sortKey deterministically
- [ ] All 6 bus combine modes implemented (sum, average, max, min, last, layer)
- [ ] Bus compilation applies adapter chains before combination
- [ ] compilePatchBusAware() replaces wire-only compiler
- [ ] Bus artifacts cached in Map<string, Artifact>
- [ ] Listener inputs resolved from compiled bus artifacts

### P0: FieldExpr Lazy Evaluation System
- [ ] FieldExpr<T> AST defined with const, map, zip, source, bus, adapter nodes
- [ ] evaluateFieldExpr() materializes expressions at consumption time
- [ ] FieldExpr combinators support functional composition
- [ ] Bus compilation produces FieldExpr artifacts
- [ ] Optimization passes implement constant folding and fusion
- [ ] FieldExpr integrates with existing bulk Field<T> boundaries
- [ ] Memoization prevents repeated evaluation

### P1: Adapter Registry and Chain Application
- [ ] Adapter interface defined with compile() transformation function
- [ ] Core adapters implemented (cast, lift, transform, collect)
- [ ] findAdapterPath() discovers conversion paths (≤2 adapters max)
- [ ] validateAdapterChain() ensures chain correctness
- [ ] Heavy adapters (Reduce, Sample) marked with warnings
- [ ] applyAdapterChain() sequentially transforms artifacts
- [ ] Adapter validation integrated into bus routing
