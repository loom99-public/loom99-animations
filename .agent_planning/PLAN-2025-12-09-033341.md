# Implementation Plan: Fix Gallery Preview Button Issue

**Generated**: 2025-12-09-033341
**Source STATUS**: STATUS-2025-12-09-033122.md
**Agent**: status-planner

## Executive Summary

**Current State**: Gallery preview button is completely non-functional in production builds. The iframe attempts to load animations using relative paths (`../animations/`) which work in Vite dev mode but fail in production, resulting in 404 errors and the gallery displaying a "tiny version of itself" in the preview iframe.

**Root Cause**: Path resolution mismatch between development and production environments. Vite dev server's `fs.allow: ['..']` configuration enables parent directory access in dev, but the built static files have no such mechanism.

**Scope**: Focused fix affecting 4 files, targeting path resolution, error handling, and build process. Estimated complexity: Medium (isolated fix with clear solution path).

**Impact**: Critical - preview functionality is a core feature of the gallery.

### P0 (Critical): Fix Animation Path Resolution in Production Build

**Status**: Not Started
**Effort**: Medium (3-5 days)
**Dependencies**: None
**Spec Reference**: README.md "View the Gallery" section • **Status Reference**: STATUS-2025-12-09-033122.md sections "Root Cause Analysis" and "Recommendations"

#### Description

The gallery's iframe preview feature uses relative paths (`../animations/${filePath}`) that fail in production builds. This causes 404 errors and results in the gallery index.html being loaded in the iframe instead of the animation file. We need to implement a build-time copy mechanism to make animation files accessible from the production dist directory.

The STATUS report identifies three potential solutions:
- **Option A**: Copy animations to dist during build (RECOMMENDED - most reliable)
- **Option B**: Symlink animations in dist (platform-dependent, may fail in some deployments)
- **Option C**: Restructure project hierarchy (too invasive for this fix)

#### Acceptance Criteria

- [ ] Animation files are accessible from production build at `/animations/` path
- [ ] Vite build process copies entire `../animations/` directory to `dist/animations/`
- [ ] Copy mechanism preserves directory structure (`logo/`, `text/` subdirs)
- [ ] AnimationCard.tsx iframe src updated to use absolute path: `/animations/${animation.filePath}`
- [ ] Dev mode continues to work (test with `pnpm dev`)
- [ ] Production build verified (test with `pnpm build && pnpm preview`)
- [ ] Manual browser testing confirms animations load in iframe
- [ ] Build size impact documented (animations directory size)
- [ ] No broken animations or missing files in dist

#### Technical Notes

**Implementation Approach**:
1. Install `vite-plugin-static-copy` for reliable cross-platform file copying during build
2. Configure plugin in `vite.config.ts` to copy `../animations/` → `dist/animations/`
3. Update `AnimationCard.tsx` line 67 to use absolute path from dist root
4. Verify both dev and production modes work correctly

**Why vite-plugin-static-copy**:
- Cross-platform compatibility (symlinks can fail on Windows or in some deployment environments)
- Explicit build-time operation (clear in build logs)
- Handles nested directory structures automatically
- Works with all deployment targets (static hosts, CDNs, etc.)

**Alternative Considered**: Manual symlink via postbuild script was rejected due to platform dependency and potential deployment issues.

### P3 (Low): Add Path Validation During Development

**Status**: Not Started
**Effort**: Small (1-2 days)
**Dependencies**: P0 (path resolution)
**Spec Reference**: gallery/README.md "Adding New Animations" • **Status Reference**: STATUS-2025-12-09-033122.md "Technical Debt Identified"

#### Description

Add development-time validation that checks if animation files referenced in metadata actually exist. This prevents adding broken references to the animations array and catches issues early.

#### Acceptance Criteria

- [ ] Create validation script that checks each animation.filePath exists
- [ ] Script runs as part of `pnpm dev` startup (via Vite plugin or pre-dev script)
- [ ] Validation checks files in `../animations/` directory
- [ ] Console warnings for missing files (non-blocking in dev)
- [ ] Build fails if animation files missing (blocking in prod)
- [ ] Clear error messages indicating which files are missing
- [ ] Support for optional animations (if needed)

#### Technical Notes

**Implementation Options**:

1. **Vite Plugin**: Custom plugin that validates files during dev server start
2. **Pre-script**: npm script that runs before `vite dev`
3. **Type-level Check**: TypeScript plugin (more complex, better IDE integration)

**Recommended**: Simple Node.js script that runs before dev/build.

**Example Script** (`scripts/validate-animations.js`):
```javascript
import { existsSync } from 'fs';
import { resolve } from 'path';
import { animations } from '../src/data/animations.ts';

const animationsRoot = resolve(__dirname, '../../animations');
const missing = [];

for (const anim of animations) {
  const fullPath = resolve(animationsRoot, anim.filePath);
  if (!existsSync(fullPath)) {
    missing.push(anim.filePath);
  }
}

if (missing.length > 0) {
  console.error('Missing animation files:');
  missing.forEach(path => console.error(`  - ${path}`));
  process.exit(1);  // Fail build
}

console.log('✓ All animation files validated');
```

**package.json Integration**:
```json
{
  "scripts": {
    "validate": "node scripts/validate-animations.js",
    "dev": "npm run validate && vite",
    "build": "npm run validate && vite build"
  }
}
```
