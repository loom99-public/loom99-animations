## Critical Issue: Memory Leak in Animation.test.ts

### Problem
Animation.test.ts (507 lines, 137 test declarations) causes Node.js to exceed 4GB heap limit before completing.

### Evidence
```
FATAL ERROR: Reached heap limit Allocation failed - JavaScript heap out of memory
Test Files  9 passed (10)
Tests       269 passed (303) - 34 Animation tests never complete
Duration    19.54s
```

### Root Cause Analysis

**File**: `/Users/bmf/code/loom99-animations/gallery/src/core/Animation.ts`

**Animation class DOES have cleanup**:
```typescript
reset(): void {
  if (this.animationFrame !== null) {
    cancelAnimationFrame(this.animationFrame);  // Line 101
    this.animationFrame = null;
  }
  this.state = 'idle';
  this.startTime = 0;
}
```

**However**, tests likely don't call `reset()` after each test, causing:
1. **507 lines of test code** with **137 test cases** create many Animation instances
2. Each test creates Animation with MockElement(s)
3. Tests await animations to complete (real requestAnimationFrame calls)
4. **Memory accumulates** across tests without cleanup
5. By test ~30-40, heap exhausted at 4GB limit

### Likely Culprits

**1. Missing afterEach cleanup in test file**:
```typescript
// Animation.test.ts likely MISSING this:
afterEach(() => {
  // No cleanup of animation instances
  // No forced garbage collection
  // RAF callbacks may still be queued
});
```

**2. Test creates many objects without disposing**:
```typescript
// With 137 tests, this accumulates:
const element = new MockElement('test-1', 10);  // Creates Track internally
const animation = new Animation({ elements: [element] });
await animation.entrance();  // Real RAF loop
// No cleanup - objects retained
```

**3. Happy-dom environment retention**:
- DOM nodes created in tests not garbage collected
- SVG elements from `toSVG()` calls retained
- Test isolation incomplete

### Impact
- ⚠️ Animation state machine NOT fully validated
- ⚠️ Cannot verify entrance → hold → exit → waiting transitions
- ⚠️ Cannot verify restart/reset behavior under load
- ⚠️ Cannot test animation cleanup/disposal
- ✅ Core Track + Compositor systems ARE validated (those 269 tests pass)

### Resolution Required

**Option A: Add test cleanup** (RECOMMENDED - quickest fix)
```typescript
// In Animation.test.ts
afterEach(() => {
  // Force garbage collection if available
  if (global.gc) {
    global.gc();
  }
});
```

**Option B: Split test file** (BETTER - isolates memory growth)
- Split Animation.test.ts (507 lines) into 3-4 smaller files
- Each file runs in separate worker process
- Memory resets between files

**Option C: Run with more memory** (WORKAROUND - doesn't fix root cause)
```bash
NODE_OPTIONS='--max-old-space-size=8192' pnpm test
```
