## Sprint Deliverables (2-3 Items Max)

### **P0: Runtime Integration Pipeline**

**Status**: Not Started
**Effort**: Medium (3-5 days)
**Dependencies**: None (Phase 1 complete)
**Spec Reference**: Section L (Runtime responsibilities) • **STATUS Reference**: STATUS-2025-01-18-164500.md Section 4 (Runtime System)

#### Description

Create the integration layer that connects UnifiedCompiler output to the Player runtime. This establishes the pull-based evaluation pipeline where the runtime:
1. Holds current state buffers
2. Calls evaluators in dependency order
3. Propagates TimeCtx through all evaluations
4. Never infers semantic meaning

The Player currently uses legacy `Program<RenderTree>` interface with `(tMs, runtimeCtx)` signature. We need to bridge from compiled evaluators to this interface while respecting the new architecture.

#### Acceptance Criteria

- [ ] Create `RuntimeAdapter` class in `gallery/src/editor/compiler/unified/RuntimeAdapter.ts` that:
  - Accepts `CompilationResult` from UnifiedCompiler
  - Produces `Program<RenderTree>` compatible with Player
  - Manages state memory Map<blockId, StateMemory>
  - Creates TimeCtx from (tMs, mode) on each frame
- [ ] RuntimeAdapter implements pull-based evaluation:
  - Evaluates blocks/buses in `evaluationOrder` sequence
  - Passes correct inputs to each evaluator from previous outputs
  - Propagates TimeCtx to all evaluator calls
  - Collects final RenderTree from output block
- [ ] State memory lifecycle:
  - Initializes state for all state blocks on program creation
  - Passes correct StateMemory to state block evaluators
  - Updates state in-place during evaluation
  - Preserves state across frames
- [ ] Add feature flag check in `gallery/src/editor/compiler/integration.ts`:
  - When `useUnifiedCompiler === true`, use UnifiedCompiler + RuntimeAdapter
  - When `useUnifiedCompiler === false`, use legacy compile path
  - No breaking changes to existing compiler API
- [ ] Unit tests for RuntimeAdapter:
  - Simple patch: constant → output (stateless)
  - Delay block patch: input → Delay → output (stateful)
  - Multi-block patch: verify evaluation order
  - State persistence: verify state survives across frames
- [ ] Integration test with Player:
  - Compile simple patch with UnifiedCompiler
  - Wrap with RuntimeAdapter
  - Load into Player
  - Verify frame rendering works
  - Verify scrubbing works (mode switching)

#### Technical Notes

**RuntimeAdapter Structure**:
```typescript
export class RuntimeAdapter {
  private compilation: CompilationResult;
  private stateMemory: Map<string, StateMemory>;
  private blockOutputs: Map<string, Record<string, unknown>>;
  private busOutputs: Map<string, unknown>;

  constructor(compilation: CompilationResult) {
    this.compilation = compilation;
    this.stateMemory = new Map(compilation.stateMemory);
    this.blockOutputs = new Map();
    this.busOutputs = new Map();
  }

  createProgram(): Program<RenderTree> {
    return {
      signal: (tMs: number, runtimeCtx: RuntimeCtx) => {
        const ctx = TimeCtxFactory.create(tMs, 0, 0, 'performance');
        return this.evaluate(ctx, runtimeCtx);
      },
      // timeline, event stubs
    };
  }

  private evaluate(ctx: TimeCtx, runtimeCtx: RuntimeCtx): RenderTree {
    // Clear outputs from previous frame
    this.blockOutputs.clear();
    this.busOutputs.clear();

    // Evaluate in dependency order
    for (const nodeId of this.compilation.evaluationOrder) {
      const block = this.compilation.blocks.find(b => b.id === nodeId);
      if (block) {
        this.evaluateBlock(block, ctx);
        continue;
      }

      const bus = this.compilation.buses.find(b => b.id === nodeId);
      if (bus) {
        this.evaluateBus(bus, ctx);
      }
    }

    // Extract RenderTree from output block
    return this.extractRenderTree();
  }
}
```

**Integration Point in integration.ts**:
```typescript
export function compilePatchToProgram(patch: EditorPatch): Program<RenderTree> {
  const flags = getFeatureFlags();

  if (flags.useUnifiedCompiler) {
    const compiler = new UnifiedCompiler();
    const patchDef = editorPatchToDefinition(patch);
    const result = compiler.compile(patchDef);

    if (result.errors.length > 0) {
      throw new CompilationError(result.errors);
    }

    const adapter = new RuntimeAdapter(result);
    return adapter.createProgram();
  }

  // Legacy path
  return legacyCompile(patch);
}
```

### **P0: Integrate State Block**

**Status**: Not Started
**Effort**: Small (1-2 days)
**Dependencies**: None (can be done in parallel with Runtime Integration)
**Spec Reference**: Section I (State: explicit, scoped, inspectable) • **STATUS Reference**: STATUS-2025-01-18-164500.md Section 5 (State Block System)

#### Description

Implement the `Integrate` state block, which accumulates a signal over time. This is the second fundamental state block (after Delay) and is essential for physics simulations, position tracking, and velocity integration.

Integrate implements: `out(t) = out(t-1) + input(t) * dt`

Must declare scrub behavior (hold by default) and respect TimeCtx.mode.

#### Acceptance Criteria

- [ ] Create `gallery/src/editor/compiler/unified/blocks/IntegrateBlock.ts`
- [ ] IntegrateBlock implements StateBlock interface:
  - `type: 'Integrate'`
  - `stateShape`: declares `accumulator: number` field
  - `scrubPolicy: 'hold'` (freeze during scrub)
  - `initState()`: initializes accumulator to 0 or initial value param
  - `updateState()`: accumulates `input * ctx.dt` when mode === 'performance'
  - `computeOutputs()`: returns current accumulator value
  - `reconstructState()`: optional, freezes accumulator during scrub
- [ ] Register IntegrateBlock in stateBlockRegistry on module load
- [ ] Support configuration parameters:
  - `initialValue: number` - starting accumulator value (default 0)
  - `resetOnLoop: boolean` - whether to reset on time wrap (default false)
- [ ] Unit tests in `gallery/src/editor/compiler/unified/__tests__/IntegrateBlock.test.ts`:
  - Basic accumulation: constant input → grows linearly
  - Zero input: accumulator stays constant
  - Negative input: accumulator decreases
  - Initial value: starts at configured value
  - Scrub mode: accumulator freezes when mode === 'scrub'
  - Multiple frames: accumulator persists across evaluations
- [ ] Integration test with UnifiedCompiler:
  - Compile patch: Constant(1.0) → Integrate → Output
  - Verify dependency graph recognizes Integrate as state block
  - Verify no instantaneous cycles detected
  - Evaluate for 100 frames, verify accumulator increases correctly

#### Technical Notes

**IntegrateBlock Implementation Pattern**:
```typescript
export const IntegrateBlock: StateBlock = {
  type: 'Integrate',

  stateShape: {
    type: 'Integrate',
    fields: {
      accumulator: { type: 'number', defaultValue: 0 },
    },
  },

  scrubPolicy: 'hold',

  initState(frame: number): StateMemory {
    return {
      shape: this.stateShape,
      values: { accumulator: 0 },
      initFrame: frame,
    };
  },

  updateState(state: StateMemory, inputs: Record<string, unknown>, ctx: TimeCtx): void {
    // Only accumulate during performance playback
    if (ctx.mode !== 'performance') return;

    const input = (inputs.input as number) ?? 0;
    const current = state.values.accumulator as number;

    // Accumulate: out = out + input * dt
    state.values.accumulator = current + (input * ctx.dt);
  },

  computeOutputs(state: StateMemory): Record<string, unknown> {
    return { output: state.values.accumulator };
  },
};

// Register on module load
stateBlockRegistry.register('Integrate', IntegrateBlock);
```

**Common Use Cases**:
- Physics: velocity → position (integrate velocity to get position)
- Rotation: angular velocity → angle
- Opacity fade: fade rate → opacity
- Phase accumulation: frequency → phase

### **P1: History State Block**

**Status**: Not Started
**Effort**: Small (1-2 days)
**Dependencies**: Integrate implementation (uses similar pattern)
**Spec Reference**: Section I (State: explicit, scoped, inspectable) • **STATUS Reference**: STATUS-2025-01-18-164500.md Section 5 (State Block System)

#### Description

Implement the `History` state block, which maintains a fixed-size circular buffer of past signal values. This enables:
- Motion trails (record past positions)
- Echo effects (access delayed copies)
- Smoothing filters (average over history)
- Pattern detection (analyze recent values)

History is the third fundamental state block and demonstrates advanced state management with buffer allocation.

#### Acceptance Criteria

- [ ] Create `gallery/src/editor/compiler/unified/blocks/HistoryBlock.ts`
- [ ] HistoryBlock implements StateBlock interface:
  - `type: 'History'`
  - `stateShape`: declares `buffer: T[]` with configurable size
  - `scrubPolicy: 'hold'` (freeze during scrub)
  - `initState()`: allocates circular buffer of specified depth
  - `updateState()`: pushes new value, maintains circular buffer
  - `computeOutputs()`: returns array of historical values (oldest to newest)
  - `reconstructState()`: optional, freezes buffer during scrub
- [ ] Support configuration parameters:
  - `depth: number` - buffer size (default 10, max 100)
  - `stride: number` - frames between samples (default 1)
- [ ] Circular buffer implementation:
  - Fixed-size array allocation in initState
  - writeIndex tracks insertion point
  - Wraps around when full (oldest data overwritten)
  - Output always returns `depth` values (padded with initial value if not full)
- [ ] Unit tests in `gallery/src/editor/compiler/unified/__tests__/HistoryBlock.test.ts`:
  - Basic recording: sequence of values recorded correctly
  - Buffer wrap: oldest values overwritten when buffer full
  - Empty buffer: returns initial values before first write
  - Depth configuration: respects configured buffer size
  - Stride configuration: samples every N frames
  - Scrub mode: buffer freezes when mode === 'scrub'
  - State persistence: buffer contents survive across frames
- [ ] Integration test with UnifiedCompiler:
  - Compile patch: Counter → History(depth=5) → Output
  - Verify buffer fills over time
  - Verify circular wrap behavior
  - Verify no memory leaks (buffer size stays constant)

#### Technical Notes

**HistoryBlock Implementation Pattern**:
```typescript
export const HistoryBlock: StateBlock = {
  type: 'History',

  stateShape: {
    type: 'History',
    fields: {
      buffer: { type: 'buffer', defaultValue: [], size: 10 }, // configurable
      writeIndex: { type: 'number', defaultValue: 0 },
      frameCounter: { type: 'number', defaultValue: 0 },
    },
    sizeHint: 10 * 8, // depth * sizeof(double)
  },

  scrubPolicy: 'hold',

  initState(frame: number, params?: { depth?: number }): StateMemory {
    const depth = params?.depth ?? 10;
    return {
      shape: this.stateShape,
      values: {
        buffer: new Array(depth).fill(0),
        writeIndex: 0,
        frameCounter: 0,
      },
      initFrame: frame,
    };
  },

  updateState(state: StateMemory, inputs: Record<string, unknown>, ctx: TimeCtx): void {
    if (ctx.mode !== 'performance') return;

    const buffer = state.values.buffer as number[];
    const writeIndex = state.values.writeIndex as number;
    const frameCounter = state.values.frameCounter as number;

    // Write new value to circular buffer
    const input = (inputs.input as number) ?? 0;
    buffer[writeIndex] = input;

    // Advance write index (circular)
    state.values.writeIndex = (writeIndex + 1) % buffer.length;
    state.values.frameCounter = frameCounter + 1;
  },

  computeOutputs(state: StateMemory): Record<string, unknown> {
    const buffer = state.values.buffer as number[];
    const writeIndex = state.values.writeIndex as number;

    // Return buffer in chronological order (oldest to newest)
    const ordered = [
      ...buffer.slice(writeIndex),
      ...buffer.slice(0, writeIndex),
    ];

    return {
      output: ordered,
      latest: buffer[(writeIndex - 1 + buffer.length) % buffer.length],
    };
  },
};
```

**Use Cases**:
- Motion trails: record path of moving object
- Smoothing: average last N values for noise reduction
- Echo: access values from T frames ago
- Pattern analysis: detect trends in recent history

## Risk Assessment

### High Risk: RuntimeAdapter Complexity
**Risk**: Bridging compiled evaluators to legacy Program interface may be more complex than anticipated
**Mitigation**: Start with simplest possible patch (constant → output), iterate to complexity
**Fallback**: Extend sprint timeline by 2-3 days if needed

### Medium Risk: State Memory Management
**Risk**: State persistence across frames could have subtle bugs (aliasing, stale references)
**Mitigation**: Comprehensive unit tests for state lifecycle, immutable state references
**Fallback**: Simplify state memory to pure immutable snapshots (slower but safer)

### Low Risk: State Block Implementation
**Risk**: Integrate/History might have edge cases in scrub mode
**Mitigation**: Follow DelayBlock pattern closely, test both modes extensively
**Fallback**: Implement simplified scrub behavior (always freeze)
