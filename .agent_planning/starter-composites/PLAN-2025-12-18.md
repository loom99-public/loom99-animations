## IMPORTANT: Composites vs Macros

**Composites** (what we're building):
- Single block in the UI that hides internal graph
- Expand at **compile time**
- User sees ONE block with exposed inputs/outputs
- Use `registerComposite()` pattern
- Example: GridPoints shows as one block, internally has DomainN + PositionMapGrid

**Macros** (different thing, NOT what we're building):
- Expand at **drop time** into visible blocks
- User sees ALL individual blocks in the patch
- Use `form: 'macro'` in block definition
- Example: MacroLineDrawing expands into ~12 visible blocks

## Goal

Build the recommended starter composites from StarterCompositeLibrary.md using the **composite** pattern (NOT macros).

## Sprint 1: Additional Arrangement Composites

### 1.1 Circle Points Composite
Uses existing PositionMapCircle primitive.

```typescript
registerComposite({
  id: 'composite:circlePoints',
  graph: {
    nodes: {
      domain: { type: 'DomainN' },
      mapper: { type: 'PositionMapCircle' },
    },
    edges: [
      { from: 'domain:domain', to: 'mapper:domain' },
    ],
    outputMap: { domain: 'domain:domain', pos: 'mapper:pos' },
  },
  exposedInputs: ['n', 'radius', 'center', 'startAngle', 'distribution'],
});
```
