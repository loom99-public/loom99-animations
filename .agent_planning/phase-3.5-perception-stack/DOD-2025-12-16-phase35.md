# Phase 3.5: Perception Stack - Definition of Done

**Generated**: 2025-12-16
**Plan Reference**: PLAN-2025-12-16-phase35.md

---

## Purpose

This document defines the acceptance criteria for the Perception Stack feature. The Perception Stack allows input ports to transform how they interpret bus signals locally.

---

## Work Item: WI-8.1 - Data Model and Types

### Type Definitions
- [ ] `PerceptionTransformType` union type defined
- [ ] `PerceptionTransform` interface defined
- [ ] `PerceptionParams` discriminated union defined
- [ ] All 8 transform types represented: identity, slew, mapRange, deadzone, quantize, threshold, integrate, wrap, fold

### Listener Interface Update
- [ ] `Listener.perception?: PerceptionTransform` field added
- [ ] Field is optional (undefined means identity)
- [ ] Serialization/deserialization works (patch save/load)

### Store Action
- [ ] `updateListenerPerception(listenerId, perception)` action added
- [ ] Action updates listener's perception field
- [ ] MobX reactivity triggers UI updates

---

## Work Item: WI-8.2 - PerceptionStack UI Component

### Transform Picker
- [ ] PerceptionStack component renders as dropdown/modal
- [ ] Shows all 8 transform options as radio buttons
- [ ] Current transform is selected/highlighted
- [ ] Clicking transform selects it

### Parameter Editors
- [ ] **Identity**: No parameters (just label)
- [ ] **Slew**: Time input (seconds)
- [ ] **Map Range**: inMin, inMax, outMin, outMax inputs
- [ ] **Deadzone**: Threshold input (±value)
- [ ] **Quantize**: Steps input (integer)
- [ ] **Threshold**: Threshold input (number)
- [ ] **Integrate**: Rate input (units/second)
- [ ] **Wrap/Fold**: Min, Max inputs + mode toggle

### UI Behavior
- [ ] Parameters show only when transform is selected
- [ ] Changes apply immediately (no confirm button)
- [ ] ESC or click-outside closes picker
- [ ] Close button available

## Work Item: WI-8.3 - PatchBay Integration

### Perception Badge
- [ ] Subscribed input ports show perception badge
- [ ] Badge shows transform name + key param: `[Slew 0.1s]`
- [ ] Identity shows `[identity]` or no badge
- [ ] Badge is clickable

### Picker Interaction
- [ ] Clicking perception badge opens PerceptionStack picker
- [ ] Picker positioned near badge
- [ ] Changes update badge immediately
- [ ] Picker closes on selection

### Badge Format by Transform
- [ ] `[identity]` or empty
- [ ] `[Slew 0.1s]`
- [ ] `[0→1 → 0→100]` (mapRange)
- [ ] `[±0.1]` (deadzone)
- [ ] `[steps: 8]` (quantize)
- [ ] `[>0.5]` (threshold)
- [ ] `[∫ 1.0/s]` (integrate)
- [ ] `[wrap 0→1]` or `[fold 0→1]`

## Work Item: WI-8.4 - Compiler Integration

### Stateless Transforms
- [ ] mapRange transform applies correctly
- [ ] deadzone transform applies correctly
- [ ] quantize transform applies correctly
- [ ] threshold transform applies correctly
- [ ] wrap transform applies correctly
- [ ] fold transform applies correctly

### Stateful Transforms
- [ ] slew transform applies correctly (smoothing over time)
- [ ] integrate transform applies correctly (accumulation)
- [ ] Runtime state maintained across frames
- [ ] State resets on listener removal

### Integration
- [ ] Bus value → perception transform → port input
- [ ] Transform applied per-listener (same bus, different transforms)
- [ ] Compilation with perception transforms produces correct program
- [ ] Runtime performance acceptable (<5ms overhead for 20 listeners)

## Definition of "DONE" for Phase 3.5

Phase 3.5 is **DONE** when:

1. ✅ All 8 perception transforms defined in type system
2. ✅ Listener interface includes perception field
3. ✅ PerceptionStack UI allows selecting and configuring transforms
4. ✅ Perception badges show current transform on port
5. ✅ Clicking badge opens picker
6. ✅ Stateless transforms apply correctly in compiler
7. ✅ Stateful transforms (slew, integrate) work with runtime state
8. ✅ Perception persists in patch save/load
9. ✅ Unit tests pass for transform functions
10. ✅ Manual testing demonstrates working perception

**Partial completion acceptable**:
- If stateful transforms (slew, integrate) prove too complex, ship Phase 3.5 with stateless transforms only
- Stateful transforms can be added in Phase 3.6 or Phase 4

## Verification Procedure

### Test 1: Basic Perception Selection

1. Create bus "energy" (number)
2. Add block with number input
3. Subscribe input to "energy"
4. Click perception badge `[identity]`
5. Select "Map Range", set 0→1 → 0→100
6. Verify badge shows `[0→1 → 0→100]`
7. Close picker

### Test 2: Multiple Perceptions on Same Bus

1. Create bus "energy"
2. Add two blocks with number inputs
3. Subscribe both to "energy"
4. Block 1: Set perception to Quantize (steps: 4)
5. Block 2: Set perception to Deadzone (±0.2)
6. Verify each port shows different badge
7. Verify each receives differently transformed value

### Test 3: Persistence

1. Complete Test 1 setup
2. Save patch
3. Clear and reload patch
4. Verify perception badge shows `[0→1 → 0→100]`
5. Click badge - verify Map Range is selected with correct params

### Test 4: Stateful Transform (if implemented)

1. Create bus "energy"
2. Add rapid-changing publisher (LFO or similar)
3. Subscribe input with Slew (0.5s)
4. Verify output smoothly tracks input
5. Compare with second input using Identity - should be choppy

If ALL tests pass (or Tests 1-3 for stateless-only), Phase 3.5 is DONE. ✅
