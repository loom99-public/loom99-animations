# Status Report: Foundational Architecture Revision
**Timestamp**: 2025-01-18-164500
**Topic**: foundational-architecture
**Key Change**: Backward compatibility is NOT a goal - old system will be removed

## Executive Summary

The editor is in a transitional state with significant architectural changes already underway. The old monolithic store has been replaced with a modular store architecture, and a new bus system has been implemented. However, these changes have not been fully integrated with the compiler and runtime systems. With backward compatibility removed, we can now accelerate the transition to the architecture specified in the Foundational Architecture document.

## Current System State

### 1. Store Architecture - PARTIALLY IMPLEMENTED
**Status**: Hybrid state between old and new architecture

**Implemented Changes**:
- ✅ Old `store.ts` deleted (replaced by modular stores)
- ✅ New store architecture with separation of concerns:
  - `RootStore.ts` - Coordinates all stores
  - `PatchStore.ts` - Manages blocks, connections, lanes
  - `BusStore.ts` - Manages signal buses and routing
  - `UIStateStore.ts` - UI state management
  - `CompositeStore.ts` - User-defined composites

**Missing Components**:
- ❌ No TimeCtx management in stores
- ❌ No explicit state block management
- ❌ Bus system exists but not integrated with compiler
- ❌ Missing evaluation pipeline state management

### 2. Bus System - IMPLEMENTED BUT NOT INTEGRATED
**Status**: Complete data structures, missing compiler integration

**What Exists**:
- ✅ Complete type system with TypeDesc (world/domain/category)
- ✅ Signal/Field world separation
- ✅ Core vs Internal domain distinction
- ✅ Bus publishers/listeners with adapter chains
- ✅ Deterministic ordering via sortKey
- ✅ Combine modes (sum, average, max, min, last, layer)

**What's Missing for Architecture Compliance**:
- ❌ No compilation to Signal evaluators or FieldExpr nodes
- ❌ No TimeCtx integration
- ❌ No domain-aware element identity
- ❌ No lazy Field evaluation at sinks

### 3. Compiler System - LEGACY
**Status**: Still using block-by-block compilation, not unified graph

**Current State**:
- ❌ Individual block compilation in `compiler/blocks/`
- ❌ No unified dependency graph (blocks + buses)
- ❌ No cycle detection across system boundaries
- ❌ Missing bus compilation contract implementation
- ❌ No explicit state boundary enforcement

**Legacy Elements to Remove**:
- Direct block-to-function compilation
- Ad-hoc connection handling
- Missing TimeCtx propagation

### 4. Runtime System - PARTIALLY COMPLIANT
**Status**: Has some concepts but needs architectural alignment

**Current Issues**:
- ❌ Runtime doesn't receive TimeCtx consistently
- ❌ No pull-based evaluation pipeline
- ❌ Missing state block management
- ❌ No bus evaluator execution

## What Needs to Be Replaced (Not Migrated)

### 1. Old Compilation Pipeline
**Files to Remove**:
```
gallery/src/compiler/blocks/          # Block-by-block compilation
gallery/src/compiler/context.ts       # Old compilation context
gallery/src/compiler/index.ts         # Old compiler entry point
```

**Why Remove**: The architecture specifies a unified dependency graph compilation, not block-by-block compilation.

### 2. Ad-hoc Connection System
**Files to Remove**:
```
gallery/src/editor/portUtils.ts       # Direct port compatibility
```

**Why Remove**: Bus system replaces all direct connections with typed signal distribution.

### 3. Legacy Time Handling
**Code Patterns to Remove**:
- Direct time passing to blocks
- Per-block time management
- Implicit state through closures

**Why Remove**: Architecture mandates single TimeCtx source for all temporal behavior.

## New Architecture Components to Build

### 1. Unified Compiler (HIGH PRIORITY)
**Purpose**: Build dependency graph, enforce architectural invariants

**Key Components**:
- Dependency graph builder (blocks + buses)
- Cycle detection across system boundaries
- Bus compilation contract implementation
- State boundary validator
- Stable ordering enforcer

**Implementation Path**:
```typescript
// New compiler structure
class UnifiedCompiler {
  compile(patch: Patch): CompiledProgram {
    const graph = this.buildDependencyGraph(patch);
    this.validateInvariants(graph);
    return this.generateEvaluators(graph);
  }
}
```

### 2. TimeCtx Manager (HIGH PRIORITY)
**Purpose**: Single source of truth for all temporal behavior

**Interface**:
```typescript
interface TimeCtx {
  t: number;        // Absolute time
  dt: number;       // Delta since last frame
  frame: number;    // Monotonic counter
  mode: 'scrub' | 'performance';
}
```

**Integration Points**:
- Runtime evaluation pipeline
- State block reconstruction
- Phase signal evaluation

### 3. Signal Bus Compilation (HIGH PRIORITY)
**Purpose**: Convert bus definitions to runtime evaluators

**Process**:
1. Collect publishers by bus with stable ordering
2. Apply adapter chains
3. Combine using domain-specific reducer
4. Generate Signal evaluator or FieldExpr node

### 4. Field Expression System (MEDIUM PRIORITY)
**Purpose**: Lazy, domain-aware expression graphs

**Key Requirements**:
- No per-element closures
- Explicit domain parameterization
- Dense batch evaluation at sinks
- Element identity stability

### 5. State Block System (MEDIUM PRIORITY)
**Purpose**: Explicit, scoped, inspectable state

**State Blocks to Implement**:
- Delay (with scrub behavior)
- Integrate (with mode handling)
- History (configurable depth)
- Explicit user state
