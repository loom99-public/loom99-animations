##### Description
Create a new compilation function that handles buses as first-class graph nodes. This is the main blocking issue preventing any progress on Phase 3.

The function must:
- Accept a BusAwareCompilerPatch instead of regular CompilerPatch
- Build a dependency graph including BusValue nodes

- Execute multi-pass compilation with bus artifact tracking
- Combine bus artifacts using 'last' mode initially

##### Acceptance Criteria

- [ ] Generated program executes without runtime errors
- [ ] Compilation time remains under 200ms for simple patches
- [ ] Error messages are clear when bus compilation fails

##### Technical Notes
- Start with 'last' combine mode only - other modes can be added later
- Skip adapter chains initially - require exact type matches
- Reuse existing block compilation logic from compilePatch
- Store bus artifacts in Map<string, CompiledArtifact[]>
- Return same CompilerResult type as existing compiler

## Risk Assessment

### High-Risk Items
1. **Compilation Complexity**: Multi-pass compilation is significantly more complex than current wire-only approach
   - Mitigation: Start with simplest possible implementation
   - Contingency: Wire-only patches remain fully functional

2. **Performance Impact**: Bus compilation could be slower
   - Mitigation: Profile implementation and optimize bottlenecks
   - Success criteria: <200ms compilation time

3. **Debug Complexity**: Bus compilation errors may be harder to trace
   - Mitigation: Add comprehensive logging and clear error messages
   - Test extensively with edge cases

### Medium-Risk Items
1. **Type System Evolution**: New types might uncover compatibility issues
   - Mitigation: Keep wire-only path completely separate
   - Maintain strict backward compatibility

2. **Test Coverage**: Edge cases in bus compilation
   - Mitigation: Start with comprehensive test suite
   - Add tests for each new feature
