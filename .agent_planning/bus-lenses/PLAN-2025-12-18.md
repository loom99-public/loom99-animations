## What Are Lenses?

From the strategy docs, lenses are transformations applied on the **listener side** of bus subscriptions. They allow:
- A `signal:phase` bus value to drive an `opacity` parameter (via easing lens)
- An `energy` bus to modulate `size` with slew/smoothing
- A `phaseA` bus to drive rotation with quantize lens for "steppy" motion

Lenses enable "binding phase/energy produces pleasing motion immediately" without requiring users to manually wire math blocks.

## Current Bus Architecture

Buses support:
- **Publishers**: Blocks that output to buses
- **Listeners**: Blocks that read from buses
- **Combine modes**: last, sum, average, max, min (for Field buses), last/sum (for Signal buses)

What's missing:
- **Lenses**: Transformations applied between bus value and target parameter

## Proposed Lens Types

From StarterCompositeLibrary.md, recommended lenses:

### Signal → Signal Lenses
1. **EaseLens** - Apply easing curve (easeIn, easeOut, easeInOut variants)
2. **SlewLens** - Smooth/slew rate limiting for gradual transitions
3. **QuantizeLens** - Snap to discrete steps for "steppy" motion
4. **ScaleLens** - Linear scale + offset
5. **WarpLens** - Phase warping (speed up/slow down parts of cycle)

### Signal → Field Broadcast Lenses
6. **BroadcastLens** - Lift scalar signal to constant field
7. **PerElementOffsetLens** - Add per-element phase offset to signal

## Implementation Approach

### Option A: Lenses as Block Parameters
Add lens configuration to existing listener definitions:
```typescript
interface Listener {
  blockId: string;
  busId: string;
  port: string;
  lens?: LensDefinition;  // NEW
}
```

### Option B: Lenses as Invisible Blocks
Insert adapter blocks between bus and target during compilation.

### Recommendation: Option A
Simpler, keeps lens configuration close to the listener, doesn't pollute block graph.

## Sprint 1: Core Lens Infrastructure

### 1.1 LensDefinition Type
```typescript
type LensType = 'ease' | 'slew' | 'quantize' | 'scale' | 'warp' | 'broadcast' | 'perElementOffset';

interface LensDefinition {
  type: LensType;
  params: Record<string, unknown>;
}
```

### 1.2 Lens Evaluation in Bus Compiler
Modify `compileBusAware.ts` to apply lens transformations when listeners have lenses configured.

### 1.3 Default Lens Presets
Ship with sensible defaults:
- `preset:breathing` - EaseLens(easeInOutSine) for gentle oscillation
- `preset:snap` - QuantizeLens(steps=4) for rhythmic motion
- `preset:smooth` - SlewLens(rate=0.1) for buttery transitions

## Sprint 2: Individual Lens Implementations

### 2.1 EaseLens
Apply easing function to 0-1 input.

### 2.2 SlewLens
Rate-limited smoothing (requires tracking previous value).

### 2.3 QuantizeLens
Snap to nearest step value.

### 2.4 ScaleLens
Linear transform: `output = input * scale + offset`

## Sprint 3: UI Integration

### 3.1 Lens Selector in Inspector
When a listener is selected, show lens configuration options.

### 3.2 Lens Presets Dropdown
Quick selection of common lens configurations.
