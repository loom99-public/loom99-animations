### 6. Track System: Support Multiple Track Groups
**File**: `gallery/src/core/Element.ts`

**Problem**: Elements can only have one set of tracks. Need separate entrance/exit track groups.

**Ambiguity**: Should tracks be:
- A) Replaced when switching from entrance to exit? (current assumption)
- B) All defined upfront with different time ranges?
- C) Separate track groups that can be swapped?

**Recommendation**: Option C - separate entrance/exit track groups:

```typescript
class BaseElement {
  protected entranceTracks: TrackGroup;
  protected exitTracks: TrackGroup;
  private activeTrackGroup: 'entrance' | 'exit' = 'entrance';
  
  getTrackValues(elapsed: number): Record<string, any> {
    const group = this.activeTrackGroup === 'entrance' 
      ? this.entranceTracks 
      : this.exitTracks;
    return group.getValues(elapsed);
  }
  
  setActiveTrackGroup(group: 'entrance' | 'exit'): void {
    this.activeTrackGroup = group;
  }
}
```

## Questions Needing Answers (if PAUSE)

**Not recommending PAUSE** because the issues are clear implementation bugs, not ambiguities. The original HTML files provide clear specifications for:
- Exit animation behavior (shoot out to edges)
- Auto-restart behavior (infinite loop)

However, one **design question remains**:

**Q1: Track Group Architecture**
How should the Track system handle entrance vs exit tracks?

**Option A**: Single track group, replace tracks when switching phases
- Pros: Simple, matches current architecture
- Cons: Requires recreating tracks, loses entrance track definitions

**Option B**: All tracks defined upfront with different time ranges
- Pros: Single timeline, could support complex sequences
- Cons: Doesn't match entrance/exit mental model, harder to reason about

**Option C**: Separate entrance/exit track groups
- Pros: Clear separation, can switch between groups without recreation
- Cons: More complex Element API, need to manage active group

**Recommendation**: Option C - matches the entrance/hold/exit lifecycle model and allows clean switching.
