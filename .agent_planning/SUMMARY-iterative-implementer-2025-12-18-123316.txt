## Proposed Approaches

### Option A: Parallel Implementation (Recommended)
- Leave existing compiler in place
- Implement new UnifiedCompiler in compiler/unified/
- Create feature flag to switch between old/new
- Migrate incrementally, remove old code when new is proven

**Pros:**
- Existing tests continue to pass
- Can validate new architecture incrementally
- Clear separation between old and new
- Matches "Option C" spirit (don't read legacy)

**Cons:**
- Temporary code duplication
- Slightly more complex during transition

### Option B: Big Bang Replacement
- Implement new compiler completely
- Delete old compiler in one commit
- Update all imports at once

**Pros:**
- Clean final state
- Forces complete implementation

**Cons:**
- High risk - nothing works until complete
- Large scope for single session
- Hard to validate incrementally

### Option C: Symlink/Adapter Pattern
- Move legacy to legacy/ folder
- Create adapter/shim layer that re-exports
- Implement new alongside

**Pros:**
- Satisfies "move to legacy" requirement
- Maintains working system

**Cons:**
- Complex import resolution
- Adds indirection
