## Executive Summary

Phase 1 (data model) and Phase 2 (Signal bus compilation) are **COMPLETE**. Phase 3 brings buses to the UI as the primary routing mechanism while maintaining wire functionality.

**The Core Mental Model**:
> You are no longer wiring a flow. You are shaping shared influence fields.

Instead of "This block feeds into that block", the user thinks:
> "These things contribute influence here, and these things respond to it."

This reframes the editor from **procedural construction** to **instrument control**.

**Current State** (from Phase 2):
- ✅ Bus, Publisher, Listener interfaces defined
- ✅ Signal bus compilation working ('last' and 'sum' modes)
- ✅ Store actions: createBus, deleteBus, addPublisher, addListener, removePublisher, removeListener
- ✅ compileBusAwarePatch() handling Signal buses
- ✅ Topological sort with bus dependencies
- ✅ sortKey-based publisher ordering

**Phase 3 Goal**: Make buses **visible, usable, and primary** in the editor UI.

**Key Constraints**:
- Wires remain functional (de-emphasized, not removed)
- Lanes will be removed (Phase 3 or Phase 4)
- Only Signal buses (Field buses deferred to Phase 4)
- Core domains only (number, vec2, color, boolean, time, phase, rate, trigger)

## New Layout Architecture

The editor resolves into four persistent regions:

```
┌───────────────────────────────────────────────┐
│ Transport / Mode Bar                          │
├───────────────┬───────────────────────────────┤
│               │                               │
│ Patch Canvas  │   Bus Board                   │
│ (Freeform)    │   (Vertical Mixer)            │
│               │                               │
│               │                               │
├───────────────┴───────────────────────────────┤
│ Inspector / Detail Panel                      │
└───────────────────────────────────────────────┘
```

**What changed from lanes**:
- No horizontal structure implying flow
- No left-to-right semantics
- No "this lane comes after that lane"
- Everything is **co-present**

### Patch Canvas (Center Stage)

A **freeform spatial canvas** where blocks live.

**What it is NOT**:
- Not ordered
- Not directional
- Not temporal

Blocks are arranged by **conceptual proximity**, not execution:
- Geometry-related blocks near each other
- Motion blocks near each other
- Color blocks near each other
- "Control / regime" blocks clustered

This mirrors how people arrange modular synths and performance rigs.

### Bus Board (The Heart of the System)

**Position**: Right side, vertically stacked, always visible.

This is intentional:
- Buses are global
- Buses are always "in reach"
- The eye learns to flick right to understand the system's state

**One-sentence principle**:
> The canvas is where behavior is built. The Bus Board is where behavior is shared and shaped.

## Bus Channel Anatomy (Mixer Channel Strip Model)

Each bus is a channel strip, like a mixer — but for influence, not audio.

### A single Bus Channel contains:

**Header**:
- Bus name (editable inline)
- Type badge (Signal / Field + domain icon)
- Active indicator (pulsing subtly if non-silent)

**Live visualization**:
- Signal: sparkline, ring, bar, or pulse dot
- Field: summary glyph (min/max band, variance stripe)
- Never per-element detail here
- This is **situational awareness**, not debugging

**Combine mode**:
- Dropdown or icon strip (sum / max / last / layer)
- Shown as "how influences coexist", not math jargon

**Publisher list (top half)**:
- Each row = one publisher
- Shows: block name + port, sortKey as vertical position, enable/mute toggle
- **Dragging rows changes sortKey (priority)**
- This is "send level & priority", not wiring

**Subscriber count (bottom hint)**:
- "Used by 5 inputs"
- Clicking reveals subscribers in inspector (not here)

## Block-to-Bus Interactions

### Output Ports (Publishers)

Every output port has:
- A small bus-send affordance (dot or plus)
- Clicking opens:
  - "Publish to existing bus…"
  - "Create new bus…"

Once published:
- **No wire is drawn**
- The relationship appears in the Bus Board, not the canvas

### Input Ports (Consumers)

Every input port has:
- A bus binding slot
- Clicking opens a bus picker filtered by compatibility

Once bound:
- The port shows: bus name + tiny transform badge (identity by default)
- No spaghetti. No ambiguity.

---

## Per-Port "Interpretation Boundary" UI (Perception Stack)

Every input port visually contains:
- The bound bus label
- A small lens / curve / waveform icon

Clicking it opens the **Perception Stack**:
- Identity (default)
- Slew
- Map range
- Deadzone
- Quantize
- Threshold
- Integrate
- Wrap / Fold

This stack is:
- Shallow (0–2 transforms common)
- Explicit
- Visible
- Local to the port

**This replaces the need for many "glue" blocks cluttering the canvas.**

*Note: Perception Stack is P2 in Phase 3, may defer to Phase 4*

---

## Wire Treatment

Wires are **not gone**. They are **demoted**.

**Used for**:
- Local structure
- Internal composite graphs
- Precise algorithmic chains

**Not used for**:
- Global modulation
- Many-to-many routing
- Expressive control

**Visually**:
- Wires fade or ghost when buses are in use
- A "Routing View" toggle can show all connections for debugging

---

## Transition Plan

### Phase 3.1: Coexistence
- Lanes still exist (but de-emphasized)
- Bus Board added
- Buses optional but encouraged

### Phase 3.2: Default Shift
- New patches start bus-first
- Lane headers removed or minimized
- Canvas becomes freeform-ish

### Phase 3.3 / Phase 4: Lane Removal
- Lane logic deleted
- Old patches migrate or remain legacy
- Bus Board becomes the organizing spine
