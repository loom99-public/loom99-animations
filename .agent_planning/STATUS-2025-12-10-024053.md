## Critical Issue: Memory Leak in Animation Tests

### Problem
Animation.test.ts causes Node.js heap to exceed 4GB limit, crashing test runner before completing.

### Evidence
```
FATAL ERROR: Reached heap limit Allocation failed - JavaScript heap out of memory
Test Files  9 passed (10) - Animation.test.ts never completes
Tests       269 passed (303) - 34 tests from Animation.test.ts missing
```

### Likely Root Causes

1. **requestAnimationFrame loops not cleaned up**:
   ```typescript
   // In Animation.ts entrance() or update()
   const tick = () => {
     this.update(elapsed);
     requestAnimationFrame(tick); // ⚠️ May not be cancelled
   };
   requestAnimationFrame(tick);
   ```

2. **Test setup accumulates objects**:
   - 34 tests × 10+ elements per test × animations not cleaned up = memory leak
   - Each test creates Animation instances that may retain references
   - requestAnimationFrame callbacks may still be queued even after test completes

3. **Happy-dom environment retention**:
   - DOM nodes created in tests not garbage collected
   - Event listeners or observers not cleaned up
   - Test isolation may not be complete

### Impact
- ⚠️ Animation state machine not fully validated
- ⚠️ Cannot verify entrance → hold → exit transitions
- ⚠️ Cannot verify restart/reset behavior
- ⚠️ Cannot test animation cleanup
- ✅ Core Track + Compositor systems ARE validated (those tests pass)

### Resolution Needed
1. Add explicit cleanup in Animation class:
   ```typescript
   private rafId: number | null = null;

   entrance() {
     if (this.rafId) cancelAnimationFrame(this.rafId);
     this.rafId = requestAnimationFrame(...);
   }

   cleanup() {
     if (this.rafId) {
       cancelAnimationFrame(this.rafId);
       this.rafId = null;
     }
   }
   ```

2. Add afterEach cleanup in Animation.test.ts:
   ```typescript
   afterEach(() => {
     // Cleanup all animations
     // Force garbage collection if possible
   });
   ```

3. Consider splitting Animation.test.ts into smaller files to isolate memory growth
