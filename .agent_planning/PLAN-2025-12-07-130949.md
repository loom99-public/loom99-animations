### P1-8: Text Animation - Liquid / Fluid Motion

**Status**: Not Started
**Complexity**: Large
**Dependencies**: P0-3 (template)
**Spec Reference**: User decision #3, technique #5

#### Description
"Do It Now" text flows into view like liquid, with ripples, surface tension effects, and fluid dynamics before solidifying.

#### Acceptance Criteria
- [ ] Fluid simulation feels realistic (or stylized-realistic)
- [ ] Text forms from liquid and becomes solid
- [ ] Performance is acceptable (fluid sims are expensive)
- [ ] Visual is striking and memorable
- [ ] File: `animations/text/05-liquid.html`

#### Technical Notes
**Challenge**: True fluid simulation is computationally expensive. Consider approaches:
- Simplified particle-based fluid using velocity fields
- SVG filter effects to simulate liquid texture (`feTurbulence`, `feDisplacementMap`)
- Blob shapes that merge and split to form letters
- Canvas-based metaball rendering

**Recommendation**: Use metaballs or blob morphing for performance. Fake the fluid physics with good easing and visual effects rather than true simulation.

## Risk Assessment

### High Risk Items

**P1-8 / P1-9 (Liquid Animations)** - COMPLEXITY
- True fluid simulation is very computationally expensive
- May need to fake the effect with simpler techniques
- Performance could be problematic
- **Mitigation**: Research metaball/blob approach first, prototype early, have simpler fallback

**P0-1 (Logo Design)** - AMBIGUITY
- Logo design is creative work, may require iteration
- Different logo types (text vs graphic) affect animation complexity
- **Mitigation**: Start simple (text-based), iterate if needed, confirm design before proceeding to all animations

### Medium Risk Items

**P2-4 (Performance Testing)** - SCOPE
- Testing 20 animations across multiple browsers/devices is time-consuming
- Optimization may uncover need to refactor animations
- **Mitigation**: Test during development, not just at end. Set performance budget early.

**P1-4 / P1-5 (Morphing)** - TECHNICAL
- Path morphing can be tricky without libraries
- Different path point counts cause visual glitches
- **Mitigation**: Research path normalization techniques, consider simple morph first

### Low Risk Items
Most individual animations (P1 items) are low-risk as they build on proven techniques from prototype. Template and structure (P0 items) are straightforward.

## Notes

**Philosophy**: Each animation should be visually distinct and showcase a different technique. Consistency in quality and polish is more important than quantity. Better to have 20 excellent animations than 20 mediocre ones.

**Development Velocity**: Each animation is estimated at 2-4 hours (Medium complexity) once template and logo are established. With template reuse and learning from previous animations, later animations will be faster.

**Testing Strategy**: Manual testing is sufficient for this project size. Automated tests would be overkill for purely visual/animation work.

**Technology Choice**: Vanilla HTML/JS/SVG is appropriate for standalone deliverables. No build system needed aligns with simplicity goal and makes animations easy to share (just open HTML file).
