## Acceptance Criteria

### Deliverable 1: Field Expression System with Domain-Aware Evaluation

#### FieldExpr Type System
- [ ] FieldExpr type complete with all node kinds: const, map, zip, source, bus, adapter
- [ ] Domain type defined with stable element IDs, ordering, optional topology
- [ ] FieldExprCtx interface with artifacts, busArtifacts, memoCache
- [ ] ElementId type defined as stable string identifier

#### FieldExpr Evaluator
- [ ] Evaluator signature: `(elementId: string, timeCtx: TimeCtx, evalCtx: FieldExprCtx) → T`
- [ ] Batch evaluator processes dense arrays at sinks (no per-element closures)
- [ ] Evaluator handles all FieldExpr node kinds (const, map, zip, source, bus, adapter)
- [ ] Memoization cache in FieldExprCtx prevents redundant evaluation per frame
- [ ] Cache keying uses FieldExpr node identity + frame number for correctness

#### Domain Validation
- [ ] Domain mismatch detection produces compile-time errors (not runtime failures)
- [ ] Domain type defined with unique ID, stable element list, optional topology
- [ ] Domain equality check compares element lists for compatibility
- [ ] Error messages clearly indicate which blocks/buses have incompatible domains

#### Field Bus Compilation
- [ ] UnifiedCompiler detects Field-world buses (vs Signal-world)
- [ ] Field buses compile to FieldExpr nodes (not Signal evaluators)
- [ ] Bus compilation collects publishers sorted by sortKey, then stable ID
- [ ] Adapter chains apply to FieldExpr nodes during bus compilation
- [ ] Combine modes (sum, average, max, min, last, layer) produce correct FieldExpr nodes
- [ ] Generated FieldExpr preserves lazy evaluation (no eager computation)

#### FieldExpr Combinators
- [ ] `map` combinator: `FieldExpr<A> + (A → B) → FieldExpr<B>`
- [ ] `zip` combinator: `FieldExpr<A> + FieldExpr<B> + (A,B → C) → FieldExpr<C>`
- [ ] Combinators compose without evaluating eagerly (preserve FieldExpr nodes)
- [ ] Function IDs registered with evaluator function registry for map/zip

#### Element Identity & Stability
- [ ] Element IDs stable across frames (same element always has same ID)
- [ ] Per-element phase offsets work correctly with domain parameterization
- [ ] No flicker from unstable element identity
- [ ] Domain elements maintain consistent ordering

#### Correctness (No Performance Testing This Phase)
- [ ] Memory usage bounded: no unbounded expression tree growth
- [ ] Memoization cache clears between frames (no stale data)

#### Testing
- [ ] FieldExpr.test.ts: 15+ tests covering node kinds, combinators, memoization
- [ ] Domain.test.ts: 8+ tests covering validation, compatibility, element stability
- [ ] FieldBusCompilation.test.ts: 10+ tests covering bus compilation, combine modes, adapters
- [ ] Integration tests: Field bus with multiple publishers compiles and evaluates correctly
- [ ] Property-based tests: FieldExpr combinators satisfy laws (identity, associativity)

#### Integration
- [ ] RuntimeAdapter provides FieldExprCtx during evaluation
- [ ] UnifiedCompiler routes Field buses to FieldExpr compilation path
- [ ] FieldExpr nodes integrate with existing Signal evaluation pipeline
- [ ] EvalCtx extended with FieldExprCtx for Field-consuming blocks

### Deliverable 2: Initial Block Migration (Scene + Phase Blocks)

#### RadialOrigin Block
- [ ] Implemented in `unified/blocks/RadialOriginBlock.ts`
- [ ] Outputs Field<Point> for per-element origin positions
- [ ] Uses FieldExpr (not closures) for origin calculation
- [ ] Parameters: centerX, centerY, radius, angleOffset (all configurable)
- [ ] Domain-aware: stable element IDs produce stable positions
- [ ] Tests (5+): smoke test, domain validation, parameter variation, edge cases, integration

#### FlowFieldOrigin Block
- [ ] Implemented in `unified/blocks/FlowFieldOriginBlock.ts`
- [ ] Outputs Field<Point> for flow field positions
- [ ] Uses FieldExpr for noise-based position calculation
- [ ] Parameters: noiseScale, flowStrength, seed (all configurable)
- [ ] Deterministic: same seed produces same positions across evaluations
- [ ] Tests (5+): smoke test, seed determinism, flow field properties, noise variation, integration

#### PhaseMachine Block
- [ ] Implemented in `unified/blocks/PhaseMachineBlock.ts`
- [ ] Outputs Signal<PhaseSample> with entrance/hold/exit lifecycle
- [ ] Uses TimeCtx for absolute time-based phase calculation (stateless)
- [ ] Parameters: entranceDuration, holdDuration, exitDuration
- [ ] Scrub-perfect: deterministic phase at any time t (no state required)
- [ ] Phase calculation: entrance [0, ed), hold [ed, ed+hd), exit [ed+hd, ed+hd+exd)
- [ ] Tests (6+): smoke test, phase transitions, scrubbing behavior, duration edge cases, lifecycle, integration

#### LinearPhase Block
- [ ] Implemented in `unified/blocks/LinearPhaseBlock.ts`
- [ ] Outputs Signal<Phase> as simple linear progression
- [ ] Uses TimeCtx for time-based evaluation
- [ ] Parameters: duration, looping (bool), offset
- [ ] Stateless: phase(t) = fract((t + offset) / duration) when looping
- [ ] Non-looping: phase(t) = clamp((t + offset) / duration, 0, 1)
- [ ] Tests (5+): smoke test, looping behavior, offset handling, edge cases, integration

#### Block Registration & Integration
- [ ] All 4 blocks register with UnifiedCompiler block registry
- [ ] Block definitions follow unified architecture pattern (BlockDefinition interface)
- [ ] All blocks use TimeCtx for temporal behavior (no hidden clocks)
- [ ] No implicit state through closures (stateless blocks)
- [ ] Block compile functions produce CompiledBlock with correct evaluator signature

#### Feature Parity with Legacy

- [ ] PhaseMachine produces identical phase samples to legacy version
- [ ] LinearPhase produces identical phase values to legacy version
- [ ] All block parameters have same semantics as legacy versions
