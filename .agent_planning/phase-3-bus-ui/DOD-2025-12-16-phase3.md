## Purpose

This document defines the acceptance criteria for each work item in Phase 3. Each criterion must be **objectively verifiable** (either it works or it doesn't, no ambiguity).

**Core Mental Model**:
> You are no longer wiring a flow. You are shaping shared influence fields.

**One-Sentence Principle**:
> The canvas is where behavior is built. The Bus Board is where behavior is shared and shaped.

## WI-1: Create Bus Board Component

### Layout Requirements (per user spec)

The editor resolves into four persistent regions:

```
┌───────────────────────────────────────────────┐
│ Transport / Mode Bar                          │
├───────────────┬───────────────────────────────┤
│               │                               │
│ Patch Canvas  │   Bus Board                   │
│ (Freeform)    │   (Vertical Mixer)            │
│               │                               │
├───────────────┴───────────────────────────────┤
│ Inspector / Detail Panel                      │
└───────────────────────────────────────────────┘
```

- [ ] Bus Board renders as right-side panel (vertical mixer style)
- [ ] Bus Board is always visible (not a modal, not hidden by default)
- [ ] Bus Board position: right side, vertically stacked
- [ ] Inspector panel below Bus Board (or at bottom)

### Channel Strip Requirements (per user spec)

Each bus channel is a "channel strip" like a mixer:

**Header**:
- [ ] Bus name displayed (editable inline)
- [ ] Type badge: Signal/Field + domain icon
- [ ] Active indicator (placeholder in Phase 3 - can be static)

**Live Visualization**:
- [ ] Visualization area present (16-24px)
- [ ] Placeholder viz shown (static in Phase 3, WI-6 for details)
- [ ] This is "situational awareness, not debugging"

**Combine Mode**:
- [ ] Combine mode displayed (dropdown or icon strip)
- [ ] Shows: sum / max / last / layer (depending on domain)
- [ ] Labeled as "how influences coexist" (not math jargon)

**Publisher List**:
- [ ] Each publisher shown as a row
- [ ] Row shows: block name + port
- [ ] sortKey determines vertical position (highest priority at top)
- [ ] Enable/mute toggle per publisher
- [ ] Dragging rows to reorder is P2 (WI-7)

**Subscriber Count**:
- [ ] Shows "Used by N inputs" at bottom
- [ ] Clicking reveals subscribers in Inspector (stub is OK for WI-1)

### Bus Board Functionality

- [ ] Shows all buses from `store.buses` as channel strips
- [ ] "New Bus" button at top of Bus Board
- [ ] Clicking "New Bus" triggers bus creation (can be stub for WI-1)
- [ ] Clicking a bus channel selects it (highlighted state)
- [ ] Selected bus triggers bus inspection in Inspector (can be stub)
- [ ] Empty state message when no buses exist
- [ ] Collapsible/expandable with state persistence

### Styling Requirements

- [ ] Channel strip visual design (card-based or list-based)
- [ ] Type badges use consistent color coding (per domain)
- [ ] Selected channel has visible highlight
- [ ] Scrollable if bus list exceeds panel height
- [ ] Minimum width: 200px
- [ ] Responsive to panel resize

### Technical Requirements

- [ ] Component uses MobX `observer` for reactivity
- [ ] Updates automatically when `store.buses` changes
- [ ] Performance: renders <16ms for 20 buses (React DevTools Profiler)

### Out of Scope for WI-1

- ❌ Live visualization (WI-6)
- ❌ Publisher reordering drag-and-drop (WI-7)
- ❌ Grouping/filtering (WI-10)
- ❌ Actual bus creation logic (WI-2)

## WI-2: Bus Creation Flow

### Path 1: From Bus Board

- [ ] Clicking "New Bus" button opens `BusCreationDialog`
- [ ] Dialog has three fields:
  - [ ] Name input (text field)
  - [ ] Type picker (Signal types only, core domains only)
  - [ ] Combine mode picker (domain-appropriate options)

### Type Picker Requirements

- [ ] Shows only Signal types (no Field types)
- [ ] Core domains only: number, vec2, color, boolean, time, phase, rate, trigger
- [ ] Uses `isBusEligible()` filter

### Combine Mode Options by Domain

- [ ] number: sum, average, max, min, last
- [ ] vec2: sum, average, last
- [ ] color: layer, last
- [ ] phase: last
- [ ] time: last
- [ ] rate: last
- [ ] trigger: or (displayed as "OR")
- [ ] boolean: or (displayed as "OR")

### Default Values (per user spec)

- [ ] Default name by domain:
  - number → "energy"
  - vec2 → "position"
  - color → "palette"
  - phase → "phaseA"
  - time → "clock"
  - rate → "speed"
  - trigger → "pulse"
  - boolean → "gate"
- [ ] Default combine mode by domain (per plan)

### Validation

- [ ] Empty name rejected (error message)
- [ ] Duplicate name rejected (case-insensitive check)
- [ ] Non-empty unique names accepted

### Dialog Behavior

- [ ] "Create" button calls `store.createBus(typeDesc, name, combineMode)`
- [ ] Dialog closes on successful creation
- [ ] New bus appears immediately in Bus Board
- [ ] "Cancel" button closes dialog without creating
- [ ] Escape key closes dialog
- [ ] Clicking outside closes dialog (optional)

### Path 2: From Output Port

- [ ] Context menu has "Create new bus from output" option
- [ ] Opens `BusCreationDialog` with pre-filled type from output slot
- [ ] After creation, auto-publishes output to new bus

### Path 3: From Input Port

- [ ] BusPicker has "Create new bus" option
- [ ] Opens `BusCreationDialog` with pre-filled type from input slot
- [ ] After creation, auto-subscribes input to new bus

### Out of Scope for WI-2

- ❌ Name auto-increment (phaseA → phaseB) - that's WI-11
- ❌ Context-aware name suggestions - that's WI-11

## WI-3: Input Port Bus Binding UI

### Bus Binding Slot Display (per user spec)

Every input port has a bus binding slot:
- [ ] All input ports show binding slot (small bus icon/dot)
- [ ] Slot position: adjacent to port circle
- [ ] Slot is clearly clickable

### BusPicker Dropdown

- [ ] Clicking binding slot opens `BusPicker` dropdown
- [ ] BusPicker positioned near clicked port (stays on screen)
- [ ] BusPicker shows:
  - [ ] List of compatible buses (exact type match)
  - [ ] "Show convertible" toggle (present but disabled in Phase 3)
  - [ ] "Create new bus of this type" button
  - [ ] Empty state: "No compatible buses" message
- [ ] Selecting a bus:
  - [ ] Calls `store.addListener(busId, blockId, port)`
  - [ ] Closes BusPicker
  - [ ] Updates port display

### Bus Subscription Badge (per user spec)

Once bound, port shows: bus name + tiny transform badge

- [ ] Badge shows: `← busName` (arrow indicates receiving)
- [ ] Transform badge shows `[identity]` by default
- [ ] Badge positioned near input port
- [ ] Badge is readable (contrasted)
- [ ] Clicking badge jumps to bus in Bus Board:
  - [ ] Scrolls Bus Board to show bus
  - [ ] Highlights bus (selected state)

### Unsubscribe Interaction

- [ ] Right-clicking input port shows context menu
- [ ] Context menu has "Disconnect from [busName]" option (if subscribed)
- [ ] Selecting it:
  - [ ] Calls `store.removeListener(listenerId)`
  - [ ] Removes badge from port

### Coexistence with Wires

- [ ] Input port can have BOTH wire connection AND bus subscription
- [ ] Both indicators visible simultaneously
- [ ] Removing wire doesn't affect bus subscription
- [ ] Removing bus subscription doesn't affect wire

### Technical Requirements

- [ ] BusPicker uses portal rendering
- [ ] Click-outside-to-close behavior
- [ ] Escape key closes BusPicker
- [ ] BusPicker updates when `store.buses` changes

### Out of Scope for WI-3

- ❌ "Show convertible" functionality - adapter chains are Phase 4
- ❌ Multiple bus subscriptions per port
- ❌ Perception Stack transforms - that's WI-8

## WI-4: Output Port Bus Publishing UI

### Bus-Send Affordance (per user spec)

Every output port has:
- [ ] A small bus-send affordance (dot or plus icon)
- [ ] Affordance is clearly clickable

### PublishMenu

- [ ] Clicking affordance opens `PublishMenu` (context menu)
- [ ] Menu positioned near clicked port (stays on screen)
- [ ] Menu structure:
  - [ ] "Publish to bus..." item with submenu of compatible buses
  - [ ] "Create new bus from output" item
  - [ ] "Stop publishing to [busName]" item (if currently publishing)

### Publish to Existing Bus

- [ ] "Publish to bus..." expands to submenu
- [ ] Submenu shows compatible buses (exact type match)
- [ ] Selecting bus:
  - [ ] Calls `store.addPublisher(busId, blockId, port)`
  - [ ] Closes menu
  - [ ] Updates port display (badge added)
- [ ] Submenu shows checkmarks for already-published buses

### Create New Bus from Output

- [ ] Opens `BusCreationDialog` with pre-filled type
- [ ] After creation:
  - [ ] Creates bus
  - [ ] Auto-publishes output to new bus
  - [ ] Badge appears on output port

### Stop Publishing

- [ ] "Stop publishing to [busName]" visible if output publishes to that bus
- [ ] Selecting it:
  - [ ] Calls `store.removePublisher(publisherId)`
  - [ ] Removes badge from port
- [ ] Separate "Stop publishing" item for each bus if publishing to multiple

### Publishing Badge Display (per user spec)

Once published, no wire is drawn. Relationship appears in Bus Board.

- [ ] Badge shows: `→ busName` (arrow indicates sending)
- [ ] Badge positioned near output port
- [ ] If publishing to multiple buses, show multiple badges
- [ ] Clicking badge jumps to bus in Bus Board

### Coexistence with Wires

- [ ] Output port can have BOTH wire connections AND bus publications
- [ ] Both indicators visible
- [ ] Removing wire doesn't affect bus publication
- [ ] Removing bus publication doesn't affect wire

### Key Principle

**No wire is drawn for bus connections.**
The relationship appears in the Bus Board, not the canvas.

### Out of Scope for WI-4

- ❌ Publisher weight/multiplier UI
- ❌ sortKey editing (automatic ordering is fine)

## Definition of "DONE" for Phase 3

Phase 3 is **DONE** when:

1. ✅ All P0 work items (WI-1 through WI-6) pass their acceptance criteria
2. ✅ Bus Board renders as vertical mixer panel (always visible)
3. ✅ Channel strips show: header, viz, combine mode, publishers, subscriber count
4. ✅ Input ports can bind to buses (no wire drawn)
5. ✅ Output ports can publish to buses (no wire drawn)
6. ✅ Bus-only patch works end-to-end
7. ✅ Mixed patch (buses + wires) works end-to-end
8. ✅ No regressions in wire-only patches
9. ✅ Mental model shift evident: "influence fields" not "wiring"

**NOT required for DONE**:
- ❌ P2/P3 work items (nice-to-have)
- ❌ Perception Stack (may defer to Phase 4)
- ❌ Lane removal (Phase 3.3 or Phase 4)
- ❌ Field buses (Phase 4)
- ❌ Live visualization sampling (Phase 4+)

## Verification Procedure

### Test 1: Bus Board Rendering

1. Open editor
2. Verify Bus Board panel visible on right side
3. Verify empty state message shown
4. Click "New Bus", create "energy" (Signal<number>, sum)
5. Verify channel strip appears with:
   - Name "energy"
   - Type badge "Signal<number>"
   - Combine mode "sum"
   - Publisher list (empty: "No publishers")
   - Subscriber count ("Used by 0 inputs")

### Test 2: Bus Creation Paths

1. Create bus from Bus Board "New Bus" button ✓
2. Add block with number output
3. Click output port, select "Create new bus from output"
4. Verify bus created with correct type, output now publishing
5. Add block with number input
6. Click input binding slot, select "Create new bus"
7. Verify bus created, input now subscribed

### Test 3: Bus-Only Patch

1. Clear patch
2. Add Clock block
3. Click Clock's "phase" output, publish to new bus "mainPhase"
4. Add Constant block (number)
5. Publish to new bus "energy" (sum)
6. Add SVGPathSource block
7. Add LineRenderer block
8. Subscribe LineRenderer inputs to buses
9. Verify compilation succeeds
10. Verify preview renders

### Test 4: Mixed Patch (Buses + Wires)

1. Clear patch
2. Add macro (creates wired blocks)
3. Create bus "energy"
4. Find block with number output, publish to "energy"
5. Find block with number input, subscribe to "energy"
6. Verify both wires and bus badges visible
7. Verify compilation succeeds
8. Verify preview renders
9. Remove bus subscription - verify wires still work
10. Re-add subscription - verify both coexist

### Test 5: Bus Inspector

1. Select bus "energy" in Bus Board
2. Verify Inspector shows bus details
3. Edit name to "globalEnergy" - verify updates
4. Change combine mode to "average" - verify updates
5. Click "Jump to block" on a publisher - verify block selected
6. Toggle publisher enable/disable - verify works

If ALL five tests pass, Phase 3 is DONE. ✅
