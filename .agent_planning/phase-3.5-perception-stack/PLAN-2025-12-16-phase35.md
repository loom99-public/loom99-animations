## Executive Summary

The Perception Stack is the "interpretation boundary" between a bus and an input port. It allows users to transform how a signal is interpreted locally at each port, replacing the need for many "glue" blocks that would otherwise clutter the canvas.

**Key Insight**: This is local to the port, not global to the bus. The same bus can be perceived differently by different ports.

---

## Core Concept

Every input port's bound bus label has a small lens/curve icon. Clicking it opens the **Perception Stack**:

```
┌─────────────────────────────────────┐
│ ← energy [Slew 0.1s]               │
│                ╰── click to open   │
└─────────────────────────────────────┘
        ↓
┌─────────────────────────────────────┐
│ Perception Stack                    │
├─────────────────────────────────────┤
│ ○ Identity (default)                │
│ ● Slew       [0.1s]                 │
│ ○ Map range  [0→1 → 0→100]          │
│ ○ Deadzone   [±0.1]                 │
│ ○ Quantize   [steps: 8]             │
│ ○ Threshold  [0.5]                  │
│ ○ Integrate  [1.0/s]                │
│ ○ Wrap/Fold  [0→1]                  │
└─────────────────────────────────────┘
```

### Stack Properties

- **Shallow**: 0–2 transforms common (most ports use Identity)
- **Explicit**: User sees exactly what transform is applied
- **Visible**: Transform badge shows on the port
- **Local**: Each port can interpret the same bus differently

## Transform Types

### 1. Identity (default)
- No transformation
- Signal passes through unchanged
- Badge: `[identity]` or no badge

### 2. Slew
- Smooths rapid changes
- Parameters: `time` (seconds)
- Example: Slew 0.1s smooths over 100ms
- Badge: `[Slew 0.1s]`

### 3. Map Range
- Remaps input range to output range
- Parameters: `inMin`, `inMax`, `outMin`, `outMax`
- Example: 0→1 mapped to 0→100
- Badge: `[0→1 → 0→100]`

### 4. Deadzone
- Ignores small values around zero
- Parameters: `threshold` (±)
- Values within threshold become 0
- Badge: `[±0.1]`

### 5. Quantize
- Snaps to discrete steps
- Parameters: `steps` (number of divisions)
- Example: 8 steps divides 0→1 into 0, 0.125, 0.25, ...
- Badge: `[steps: 8]`

### 6. Threshold
- Binary output based on threshold
- Parameters: `threshold`
- Output: 0 if below, 1 if at or above
- Badge: `[>0.5]`

### 7. Integrate
- Accumulates value over time
- Parameters: `rate` (units per second)
- Badge: `[∫ 1.0/s]`

### 8. Wrap/Fold
- Wraps or folds values to range
- Parameters: `min`, `max`, `mode` (wrap/fold)
- Badge: `[wrap 0→1]` or `[fold 0→1]`

## Compiler Integration

The compiler must apply perception transforms when evaluating bus→listener connections.

### Transform Application Order

1. Bus value is evaluated (from combined publishers)
2. Perception transform is applied (per listener)
3. Result is passed to the block's input port

### Implementation Approach

```typescript
// In bus compilation
function applyPerception(value: number, perception?: PerceptionTransform): number {
  if (!perception || perception.type === 'identity') {
    return value;
  }

  switch (perception.type) {
    case 'slew':
      // Requires state - track previous value
      return slewFilter(value, perception.params.time, dt, prevValue);
    case 'mapRange':
      return mapRange(value, perception.params);
    case 'deadzone':
      return Math.abs(value) < perception.params.threshold ? 0 : value;
    case 'quantize':
      return quantize(value, perception.params.steps);
    case 'threshold':
      return value >= perception.params.threshold ? 1 : 0;
    case 'integrate':
      // Requires state - accumulate over time
      return integrate(value, perception.params.rate, dt, accumulator);
    case 'wrap':
      return wrap(value, perception.params.min, perception.params.max);
    case 'fold':
      return fold(value, perception.params.min, perception.params.max);
  }
}
```

### Stateful Transforms

Some transforms (slew, integrate) require state that persists across frames:
- **Slew**: Previous value for smoothing
- **Integrate**: Accumulated value

Options:
1. Store state in listener object (runtime state, not serialized)
2. Use a separate runtime state map keyed by listenerId
3. Generate stateful code in compiled program

## Risk Assessment

### High Risk
1. **Stateful transforms complexity**: Slew and Integrate require frame-persistent state
   - Mitigation: Start with stateless transforms, add stateful later
   - Contingency: Defer stateful transforms to Phase 4

### Medium Risk
1. **Compiler complexity**: Adding transform layer to bus evaluation
   - Mitigation: Clean abstraction, isolated transform functions

2. **UX complexity**: Too many transform options might confuse users
   - Mitigation: Good defaults, hide advanced options initially

### Low Risk
1. **Type system**: Well-defined discriminated unions
2. **UI complexity**: Similar patterns to existing pickers
