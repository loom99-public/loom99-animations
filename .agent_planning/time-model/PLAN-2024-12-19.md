# TimeModel Implementation Plan

## Reference Spec
`feature_planning_docs/PlayerTimeDesign.md` - authoritative technical specification

## Goal
Implement the foundational pieces of the TimeModel architecture so that:
1. Compiler outputs TimeModel alongside Program
2. Player consumes TimeModel instead of hardcoded maxTime
3. Time wrapping moves from player to signal layer

---

## Increment 1: Define TimeModel Types & Compiler Output Contract

### Objective
Create the type system and update compiler to output `{ program, timeModel }`.

### Changes

**1.1 Define TimeModel types** (`gallery/src/editor/compiler/types.ts`)
- Add `TimeModel` discriminated union:
  - `FiniteTimeModel { kind: 'finite', durationMs: number }`
  - `CyclicTimeModel { kind: 'cyclic', periodMs: number, phaseDomain: '0..1' }`
  - `InfiniteTimeModel { kind: 'infinite', windowMs: number }`
- Add `CompiledProgram { program: Program<RenderTree>, timeModel: TimeModel }`
- Remove `TimelineHint` type (deprecated)

**1.2 Update compiler output** (`gallery/src/editor/compiler/compile.ts`)
- Change return type from `Program<RenderTree>` to `CompiledProgram`
- For now, infer a simple TimeModel:
  - If patch has PhaseClock with mode='loop' → `CyclicTimeModel`
  - If patch has PhaseMachine → `FiniteTimeModel` with computed duration
  - Default → `InfiniteTimeModel { windowMs: 10000 }`

**1.3 Update all call sites**
- `PreviewPanel.tsx` - destructure `{ program, timeModel }` from compilation
- Any other places that call the compiler

### Acceptance Criteria
- [ ] TimeModel types defined and exported
- [ ] TimelineHint removed (or deprecated with TODO)
- [ ] Compiler returns CompiledProgram
- [ ] All call sites updated, tests pass
- [ ] Console.log timeModel on compilation to verify inference

---

## Increment 2: Player Consumes TimeModel

### Objective
Player receives TimeModel and uses it to configure time behavior. Remove hardcoded maxTime wrapping.

### Changes

**2.1 Add `applyTimeModel()` to player** (`gallery/src/editor/runtime/player.ts`)
```typescript
applyTimeModel(timeModel: TimeModel): void {
  this.timeModel = timeModel;
  // Configure based on kind:
  // - finite: set maxTime for UI scrubber bounds
  // - cyclic: set period for phase-based UI
  // - infinite: set windowMs for sliding window
}
```

**2.2 Remove time wrapping from tick()**
- Delete `time = time % maxTime` logic
- Time becomes unbounded: `time += dt * speed`
- Looping/wrapping happens in signals, not player

**2.3 Update PreviewPanel to pass TimeModel**
- After compilation, call `player.applyTimeModel(timeModel)`
- Update scrubber/UI to reflect TimeModel kind (basic implementation)

**2.4 Phase signals handle their own wrapping**
- PhaseClock already does `t % period` internally - this is correct
- Player just feeds unbounded time

### Acceptance Criteria
- [ ] Player has `applyTimeModel()` method
- [ ] Player tick() no longer wraps time
- [ ] PreviewPanel passes TimeModel to player
- [ ] Cyclic animations loop correctly via signal layer
- [ ] Finite animations stop/clamp correctly
- [ ] Tests pass

## Out of Scope (Future Increments)

- Multiple phase detection and primary cycle selection
- Hot-swap during playback
- Phase offset injection for scrubbing
- UI indicators for infinite/cyclic/finite
