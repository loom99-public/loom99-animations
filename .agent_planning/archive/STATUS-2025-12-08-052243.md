**Variance Model**:
- **Original**: All lines converge from single off-canvas point
- **Varied**: Random mode selection (converge, cascade, diagonal) on each restart
- **Procedural**: Full parameter control via URL (duration, stagger, hueShift, holdDuration)

### Level 1: Track

```typescript
class Track<T> {
    constructor(
        public from: T,
        public to: T,
        public duration: number,
        public delay: number = 0,
        public easing: EasingFunction = linear
    ) {}

    getValue(t: number): T {
        if (t < this.delay) return this.from;
        const localT = (t - this.delay) / this.duration;
        const progress = Math.min(1, localT);
        const eased = this.easing(progress);
        return this.interpolate(this.from, this.to, eased);
    }

    protected interpolate(a: T, b: T, t: number): T {
        // Type-specific interpolation
        // number: a + (b - a) * t
        // {x, y}: { x: lerp(a.x, b.x, t), y: lerp(a.y, b.y, t) }
        // path: morphPath(a, b, t)
        // color: lerpHSL(a, b, t)
    }
}
```

### Level 3: Animation

```typescript
class Animation {
    elements: AnimatedElement[];
    state: 'entrance' | 'hold' | 'exit' | 'waiting';

    entrance(): void {
        this.state = 'entrance';
        this.startTime = performance.now();
        this.loop();
    }

    exit(): void {
        this.state = 'exit';
        this.exitStartTime = performance.now();
    }

    private loop(): void {
        const t = performance.now() - this.startTime;

        if (this.state === 'entrance') {
            this.elements.forEach(el => el.update(t));

            if (this.isComplete()) {
                this.state = 'hold';
                setTimeout(() => this.exit(), this.holdDuration);
            }
        } else if (this.state === 'exit') {
            const exitT = performance.now() - this.exitStartTime;
            this.elements.forEach(el => el.updateExit(exitT));

            if (exitT >= this.exitDuration) {
                this.state = 'waiting';
                return; // Stop loop
            }
        }

        requestAnimationFrame(() => this.loop());
    }
}
```

### Critical Challenges for Track-Based Model

#### Challenge 1: Wave/Ripple Doesn't Fit Track Model

**Problem**: Wave animations use continuous oscillation, not 0→1 interpolation.

```javascript
// Current wave logic
const y = Math.sin(time * 4 + wavePhase) * amplitude * decayFactor;
```

**Track equivalent would be**:
```typescript
class OscillatingTrack extends Track<number> {
    constructor(
        public frequency: number,
        public amplitude: number,
        public phase: number,
        public decayRate: number
    ) {}

    getValue(t: number): number {
        const decay = Math.max(0, 1 - t * this.decayRate);
        return Math.sin(t * this.frequency + this.phase) * this.amplitude * decay;
    }
}
```

✅ **Solvable**: Custom track types handle this

#### Challenge 2: Particle Count Doesn't Fit Element Model

**Problem**: Particle animations have 1000-3000 particles, creating 1000-3000 AnimatedElement instances is expensive.

**Solution**: Batch rendering
```typescript
class ParticleAnimation extends Animation {
    particles: Particle[]; // Plain data objects, not AnimatedElements

    update(t: number): void {
        // Update all particles in batch
        // Single canvas render pass
    }
}
```

✅ **Solvable**: Particle animations are special case, don't use Element abstraction

#### Challenge 3: Glitch Random Jitter Doesn't Fit Track Model

**Problem**: Glitch applies random offsets each frame, not smooth interpolation.

```javascript
// Current glitch logic
const jitterX = (Math.random() - 0.5) * glitchIntensity;
const jitterY = (Math.random() - 0.5) * glitchIntensity;
```

**Track equivalent**:
```typescript
class NoiseTrack extends Track<{x: number, y: number}> {
    getValue(t: number): {x: number, y: number} {
        return {
            x: (Math.random() - 0.5) * this.amplitude,
            y: (Math.random() - 0.5) * this.amplitude
        };
    }
}
```

✅ **Solvable**: Noise/random tracks are a track type

#### Challenge 4: Multi-Phase Line Drawing

**Problem**: Line drawing has TWO sequential phases with different logic:
1. Phase 1: Shoot in (0-70% of duration)
2. Phase 2: Fold into shape (70-100% of duration)

**Current code**:
```javascript
if (localTime < this.duration * 0.7) {
    // Shoot-in logic
} else {
    // Fold logic
}
```

**Track equivalent**: Compound track or sequential tracks

```typescript
class CompoundTrack<T> {
    phases: Array<{ duration: number, track: Track<T> }>;

    getValue(t: number): T {
        let elapsed = t;
        for (const phase of this.phases) {
            if (elapsed < phase.duration) {
                return phase.track.getValue(elapsed);
            }
            elapsed -= phase.duration;
        }
        return this.phases[this.phases.length - 1].track.to;
    }
}
```

⚠️ **Solvable but complex**: Need compound/sequential track types

#### Challenge 5: Typewriter Discrete Steps

**Problem**: Typewriter reveals letters one-at-a-time (discrete), not smooth interpolation.

**Current**:
```javascript
const letterIndex = Math.floor(elapsed / letterDuration);
letters[letterIndex].style.opacity = '1';
```

**Track equivalent**:
```typescript
class StepTrack<T> extends Track<T> {
    constructor(public steps: T[], public stepDuration: number) {}

    getValue(t: number): T {
        const index = Math.min(this.steps.length - 1, Math.floor(t / this.stepDuration));
        return this.steps[index];
    }
}
```

✅ **Solvable**: Step/discrete track type

## Critical Concerns (From ENGINE-FLEXIBILITY-ANALYSIS.md)

### Concern 1: Variant-Specific Code That Doesn't Fit Config Model

**Problem**: Varied animations regenerate random parameters on EACH restart, not just at initialization.

**Impact on Track Architecture**:
- Need `onRestart()` hook that returns new track configurations
- OR need `updateConfig()` method to hot-swap tracks
- Current track design assumes static configuration

**Solution**:
```typescript
interface AnimationHooks {
    onRestart?: () => TrackConfiguration;
}

class Animation {
    constructor(
        private initialConfig: TrackConfiguration,
        private hooks?: AnimationHooks
    ) {}

    restart(): void {
        if (this.hooks?.onRestart) {
            this.config = this.hooks.onRestart();
            this.rebuiltracks();
        }
        this.entrance();
    }
}
```

✅ **Addressable**: Add hook system to track architecture

### Concern 2: Target-Specific Code (Logo vs Text)

**Investigation Result**: Logo and text ARE identical except for data.

**Differences**:
- SVG path data
- Viewport dimensions
- Colors
- Stroke widths

**All are DATA, not LOGIC differences.**

✅ **Not a concern**: Validated assumption is correct

### Concern 3: Dynamic Text Feature (postMessage API)

**Investigation**: Some files have dynamic text via postMessage:

```javascript
window.addEventListener('message', (event) => {
    const newText = event.data.text;
```

```typescript
        const newPaths = generatePathsFromText(newText, this.fontConfig);
        this.elements = this.createElementsFromPaths(newPaths);

}

}
```

⚠️ **Addressable but adds complexity**: Need font loading and path generation

### Concern 4: Configuration Explosion

**Problem**: Track-based system could lead to 30+ parameters per animation.

**Example**:
```typescript
{
    timing: { duration, delay, stagger, holdDuration, exitDuration },
    colors: { hueShift, satShift, lightShift },
    motion: { startX, startY, angle, distance },
    effects: { strokeWidth, glowRadius },
    // ... 20 more properties
}
```

**Solution**: Preset system with overrides

```typescript
const LineDrawingPresets = {
    original: (): LineDrawingConfig => ({
        timing: { duration: 1500, delay: 0, stagger: 50 },
        // ... full config
    }),

    moderate: (): LineDrawingConfig => ({
        ...LineDrawingPresets.original(),
        timing: {
            ...LineDrawingPresets.original().timing,
            durationVariance: 0.3,
            staggerVariance: 0.2
        }
    }),

    heavy: (): LineDrawingConfig => ({
        // Maximum variance
    })
};

// Usage
const config = LineDrawingPresets.moderate();
config.timing.duration = 2000; // Override just what you need
```

✅ **Addressable**: Preset system is a known pattern

### Concern 5: Loss of Direct Control

**Problem**: "I want varied, but with THIS specific easing function for the first line only"

**Current**: Just edit the code directly
**Track-based**: Need per-element override system

**Solution**: Per-track overrides

```typescript
animation.addElement({
    id: 'line-0',
    tracks: {
        x: new Track(startX, endX, duration, 0, easeOutQuart),
        y: new Track(startY, endY, duration, 0, customEasingForThisLineOnly)
    }
});
```

✅ **Addressable**: Tracks are configurable per-element
